# Verify the result collector

**Property:** Each completed result belongs to its outcome, its completion event includes the counts captured when it was added, and a report snapshot's outcome counts match its copied lists. Editing a report must not change the collector's lists. A wrong bucket or snapshot can give users an incorrect mutation score or hide an escaped mutant.

Run `.agents/skills/verify-result-collector/check.sh` from the repository root. It requires Go, Java, Python 3, Bash, curl and shasum. It downloads a checksum-pinned TLC 1.7.4 on first use. TLC checks `Collector.tla` with two result invocations and two outcomes, including completion callbacks delivered out of recording order and a report captured while other results may still arrive. The model separately captures the report and publishes its summary so other actions may occur between those steps. Deliberately broken event and report counts must violate their named model invariants. A Go overlay probe checks all five outcomes, completion callback identity and counts, summary publication, report counts and isolation from later report edits. Four scratch overlays independently break the escaped bucket, completion counts, report count and report copying; each must fail for its named reason before the clean probe passes. The overlays do not modify the checkout.

The covered production functions are `completedResults.record`, `add`, `list`, `countsLocked`, `stats`, `fill`, `summarize`, and `cloneMutants` in `internal/engine/results.go`; `models.RunListener` and `models.Stats` in `internal/models`; and `Report.Calculate` insofar as the summary preserves outcome counts. Last matched to `8df20e1d4be438203689f540acf6138d7d8fb89c`. Compare changes since that commit and uncommitted changes to the model and probe; update them for intended behavior and advance the sync point only after checking the mapping and passing the check. Read every model result with `/statechart`, using `Collector.tla`, `Collector.cfg` and `view.mjs`. Replay any counterexample against the covered functions. A compiler error, timeout or unrelated assertion is not a successful fault detection.

The model treats each locked add or fill as an atomic step and represents each `record` invocation once; it does not assume mutant IDs are unique in the real implementation. It models two outcomes rather than five and one `summarize` invocation, with stored entries as sets rather than ordered slices. It does not prove the Go mutex, listener implementation, progress callbacks, numeric score calculation, per-mutator breakdown, repeated summaries, process failures, liveness, or all possible scheduler interleavings. The engine's shutdown protocol establishes when producers stop and is checked separately by `/verify-run-shutdown`; this model deliberately permits summary snapshots before that point. Go fault probes are representative, not a proof of correspondence for all executions. A report is intentionally mutable after it is published; isolation means edits to its copied lists do not mutate the collector, not that listeners cannot edit the report itself.
