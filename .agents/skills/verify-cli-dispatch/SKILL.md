# Verify CLI dispatch and interrupts

Version, help and mutator-list requests must be handled in that order before parse or configuration errors when the corresponding flag has been parsed. After an interrupt is received, signal interception must stop before the run's context is cancelled, so a subsequent signal has its default effect even while cleanup is running.

Run `./.agents/skills/verify-cli-dispatch/check.sh` from the repository root. It requires Bash, Python 3, Go, Java and a checksum-pinned TLC jar downloaded on first use. The Go overlay enumerates all 16 combinations of version, help, list and completion state against the real early-exit implementation and checks selected argument/error precedence cases. A process test sends each of SIGINT and SIGTERM, waits until the real interrupt owner publishes cancellation, then requires the same second signal to terminate the process. The interrupt model explores signal receipt, the goroutine select, normal-close cancellation, unregistration and cancellation. It checks that interrupt-caused cancellation follows unregistration and that close waits for unregistration. `Dispatch.tla` explores early exit, parse and completion, configuration, target, baseline and info/run dispatch decisions in order. The scratch variants disable the version branch, omit signal unregistration or bypass target validation; the corresponding checks must fail for their stated reasons, after which the unmodified code is checked again.

The dispatch model assumes the early-exit decision is already resolved, target discovery and baseline loading are atomic, and configuration has a boolean success result. It does not model all argument orders, config merging, target discovery internals, baseline contents, or info output. Concrete checks exercise config-before-target, target-before-baseline, baseline-before-info and file-list success; they do not exhaust path and configuration variants. The signal model abstracts signal delivery and the standard library's `signal.Stop` guarantee. It represents interrupt-caused cancellation, including normal close, but not signal delivery before registration. The real subprocess test checks a second identical signal after observing cancellation, not every possible timing or a mixed signal pair. It does not prove engine cleanup. Existing CLI process tests cover cleanup after cancellation. A compiler error, timeout unrelated to the intended missing stop, or setup failure does not count as sensitivity evidence. For a model failure reproduce its steps against the Go code before changing the model.
